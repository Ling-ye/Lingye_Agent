# Security Policy / 安全策略

## Supported versions / 支持版本

| Version / 版本 | Supported / 支持状态 |
|---|---|
| 0.1.x | Beta security fixes / Beta 安全修复 |
| Earlier commits / 更早提交 | Not supported / 不支持 |

## 中文报告流程

请使用 GitHub 仓库 Security 页面中的私密漏洞报告功能。不要在公开 Issue、Discussion、Pull Request 或日志中提交以下内容：

- API Key、访问令牌、密码或私钥；
- 可识别用户的记忆、数据库、提示或检索内容；
- 可直接利用的复现步骤或未修复漏洞细节。

报告应包含受影响版本、影响范围、最小复现、预期与实际行为，以及你已采取的临时缓解措施。对于不含敏感细节的一般 Bug，请使用公开 Issue。

维护者会先确认报告是否可复现，再决定修复与披露时间。Beta 版本不承诺固定响应时限。

## English reporting process

Use private vulnerability reporting from the repository's Security page. Do not post the following in a public issue, discussion, pull request, or log:

- API keys, access tokens, passwords, or private keys;
- identifiable user memory, databases, prompts, or retrieved content;
- directly exploitable reproduction steps or details of an unpatched vulnerability.

Include the affected version, impact, minimal reproduction, expected and actual behavior, and any temporary mitigation you have applied. Use a public issue for ordinary bugs that contain no sensitive details.

Maintainers will first verify reproducibility, then decide the fix and disclosure timeline. Beta releases do not promise a fixed response time.
